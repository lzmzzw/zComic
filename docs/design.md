# zComic 功能与技术方案（初稿）

## 目标与边界

zComic 服务于两台个人 Android 设备，最低 Android 15。用户通过自己的 Kmoe 账号检索漫画，选择多个单卷 EPUB 加入下载队列，将文件保存到系统 `Documents/zComic`，再在应用内阅读。两台设备的记录相互独立。

第一版不做收藏、跨设备同步、VIP 批量下载、自动购买或自动解锁，也不要求退出应用后继续下载。网站访问、可下载内容和额度均以账号实际权限为准。

## 功能设计

### 账号

- 首次打开时在应用内输入账号和密码，后台提交登录，不跳转网站登录页。
- 登录状态过期时自动重新登录；自动登录失败或站点要求额外验证时，提示重新输入或人工处理。不绕过验证码或站点限制。
- 凭据只保存在设备的受保护存储中；不写入 APK。退出登录时清除本地凭据和会话，已下载 EPUB 与阅读位置是否同时删除需在界面中分别选择，默认保留。

### 发现与下载

- “发现”页提供关键词搜索和网站“最近更新”列表。列表显示封面、名称及网站可提供的简要信息。
- 详情页显示漫画信息和可用卷册。卷册展示卷号、文件大小、页数及本地状态；支持多选后加入队列。非 VIP 账号只走单卷下载入口。
- 队列最多同时下载 2 卷，其余等待。每个入口失败后自动重试 2 次；优先“下载二”，仍失败再尝试“下载一”。失败项保留在队列，允许手动重试或取消。重复加入已完成或已排队卷册时不给出第二个任务。
- 应用关闭后暂停下载；再次打开时自动恢复未完成任务。用户可主动暂停、继续、取消。网络不限 Wi-Fi。下载进度显示已接收字节、总大小（若可得）和状态。
- 仅在服务端支持字节范围请求且临时文件与当前资源匹配时续传；否则重新下载该卷。完成前校验文件可作为 EPUB 打开，再原子化写入公开目录。下载链接过期时重新取得链接，不沿用过期地址。
- 文件保存在 `Documents/zComic/<漫画名>/<卷名>.epub`，路径组件需清理非法字符并避免不同作品或卷册清理后重名。同名文件默认跳过，不覆盖；若同名文件内容不属于该卷，显示冲突并由用户处理。

### 书架与阅读

- 书架显示应用下载和本地导入的 EPUB、各卷上次阅读位置及下载记录；不提供网站收藏。首次扫描已有 `Documents/zComic` 文件时请求用户选择该目录并持久保存系统授权。启动和进入书架时核对可访问文件，已被外部删除或移动的卷册自动从书架及阅读记录中移除。
- 支持通过应用内文件选择器导入 EPUB，也支持在文件管理器中使用“打开方式”选择 zComic。外部文件经校验后复制进 `Documents/zComic`，加入书架；同一文件再次导入时复用已有条目，不生成副本。同名但内容不同的文件提示冲突，不覆盖。
- 书架允许删除已下载或已导入的卷册。删除时同时删除受 zComic 管理的文件和该卷阅读位置，并在操作前确认；若文件删除失败，保留书架记录并提示失败，避免只清除记录。
- 阅读器支持从左往右、从右往左的分页，以及上下连续阅读；支持双指缩放、横竖屏切换、适应宽度与适应整页。横屏保持单页显示。
- 每卷保存上次阅读位置，切换阅读模式或屏幕方向后尽量定位到同一原始图页；缩放比例不持久化。阅读记录只在本机保存。
- EPUB 只按实际文件内容解析，优先兼容图片型漫画 EPUB。损坏、加密或不支持的排版应给出明确错误，不标为可阅读。

## 页面结构

底部导航为“书架”“发现”“下载”，启动默认书架。发现页进入搜索结果或最近更新，再进入漫画详情；详情页多选卷册并加入下载队列。下载页在同一列表查看等待、下载中、暂停、失败和完成状态。书架提供导入、扫描与删除，点击作品查看各卷或继续阅读；阅读器菜单切换翻页方向、连续模式、适应宽度/整页和背景。账号入口位于设置中。具体布局见 [页面设计](pages.md)。

## 技术方案

- 原生 Kotlin Android 应用，界面建议采用 Jetpack Compose，最低 SDK 35。站点访问封装为独立数据源，避免把 HTML 结构和链接规则散布到界面或下载模块。
- 使用同一受控 HTTP 会话管理登录、Cookie、搜索、详情与下载。网页结构可能变化，解析失败要区分“登录失效”“权限不足”“页面结构变化”和网络故障。
- 使用 Room 保存漫画、卷册、下载任务与阅读位置；凭据使用 Android Keystore 保护的本地加密数据。数据库不得保存明文密码、完整带身份参数的下载链接或 EPUB 正文。
- 下载在应用进程运行期间由持久队列执行；任务状态和临时文件可恢复。退出或进程终止后不保证继续下载，再次打开应用自动接续。应用新建的公开文件通过 MediaStore 写入 `Documents/zComic`；扫描该目录中其他应用创建的既有文件时，通过系统目录选择器取得持久授权，不申请所有文件管理权限。
- 下载先写应用私有临时文件，校验 EPUB ZIP 结构与必要元数据后再发布到 `Documents/zComic`。仅在目标内容一致且服务端支持 Range 时续传；取消任务清理临时文件。文件名冲突跳过且保留原文件。
- EPUB 阅读采用成熟解析库处理容器、目录与资源，再针对图片页实现分页和连续模式。先以真实样本验证图片顺序、跨页图、旋转和大图内存占用，再确定具体库和渲染组件。位置以 EPUB 内图页或内容资源标识保存，屏幕方向变化不依赖像素偏移。
- `ACTION_OPEN_DOCUMENT` 负责应用内导入，`ACTION_VIEW` 接收文件管理器打开的 EPUB。两种入口都先验证文件并计算内容标识，再复制进管理目录或复用已有文件。导入来源的原文件不删除；书架删除只作用于 zComic 管理目录中的副本。

## 实施前验证

1. 在用户授权的账号会话中确认后台登录请求、Cookie 生命周期、是否存在验证码或额外验证。验证时不记录或输出密码、Cookie。
2. 验证搜索、最近更新、详情与卷册数据的稳定入口；确认非 VIP 的“下载二”“下载一”实际流程、额度和错误响应。截图只证明页面提供这些控件，不证明接口可直接调用。
3. 对各下载入口检查重定向、文件类型、大小、链接时效及 HTTP Range/ETag 行为；据此确定断点续传可用范围。若不支持 Range，产品仍提供失败后重新下载和应用重开自动重试。
4. 用至少一卷实际取得的 EPUB 验证图片型阅读、翻页方向、连续模式和阅读位置映射。测试大文件下载与低内存设备上的解码行为。
5. 真机验证 Android 15 的 `Documents/zComic` 可见性、目录授权、既有文件扫描、文件管理器“打开方式”、同名跳过、外部删除后的书架清理，以及应用被系统终止后的队列恢复。

## 后续验证与调整

目录扫描、外部 EPUB 打开和删除行为需在两台目标设备上验证。若厂商文件管理器不提供标准 `ACTION_VIEW` URI，仍保留应用内导入入口。横屏单页的缩放和位置保持需用图片型 EPUB 样本验收。
